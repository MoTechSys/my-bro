## 1. النية المعتمَدة (بعد التوفيق بين docs/05 وT-17)

> **نبني طبقة تكامل وتشغيل فوق Wazuh تُوحِّد إشارات الأجهزة الطرفية (Windows/Linux) وأجهزة الشبكة (router/switch عبر syslog) وحركة الشبكة (Suricata) في خط أنابيب واحد — كشف → قرار محكوم بسياسة → استجابة آلية محدودة وآمنة → عرض — ونُثبت فعاليتها بسيناريوهات هجوم مُقاسة منهجياً، ونُصمّمها بحيث يُضاف مصدر جديد (بما فيه رؤية الهواتف من الشبكة) دون تغيير المعمارية.**

**ما تغيّر عن جملة docs/05:** إضافة "أجهزة الشبكة" و"رؤية الهواتف من الشبكة" للنطاق الصريح، وإضافة "محكوم بسياسة" و"محدودة وآمنة" للاستجابة (نتيجة T-15).

**العنوان يبقى:** *Design and Implementation of an Open-Source SOC Platform with Automated Threat Response using Wazuh and Suricata* — لا يتغيّر لأنه يغطي التوسّع.

## 5. تعريفات القياس المعتمَدة (من T-11 — لا تُغيَّر بعد الآن)

| المقياس | التعريف الدقيق | لماذا هكذا |
|---|---|---|
| **Detection Rate** | محاولات صالحة أنتجت التنبيه المتوقع ÷ كل المحاولات الصالحة | الفاشلة تُحسب؛ المستبعَدة تُوثَّق بسبب |
| **MTTD (source→manager)** | `alert.timestamp` − وقت الحدث في سجل المصدر (auditd/eve.json/syscheck) | يفصل زمن الخط عن زمن اللوحة |
| **Visibility latency** | وقت ظهور التنبيه في Dashboard query − `alert.timestamp` | Indexer/refresh interval |
| **AR completion** | وقت اكتمال الفعل الفعلي (ملف اختفى / IP محظور) − وقت trigger | ≠ تنبيه التأكيد 100092 |
| **FP/hour** | تنبيهات L≥7 غير مُبرَّرة خلال baseline ÷ ساعات التعرض (union، لا جمع مزدوج) | adjudication بشري لكل تنبيه |
| **Clock uncertainty** | يُقاس NTP offset لكل جهاز قبل كل جلسة ويُسجَّل | بدونه Δt بلا معنى |

**ممنوع:** "نجاح 100%"، mean بدون توزيع، أرقام من لقطات قديمة، دمج PILOT مع MEASURED.
