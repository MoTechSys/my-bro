## 1. ما قاله الفريق (ملخص أمين)
1. النظام الحالي يراقب Windows/Linux ويرسل تنبيهات (FIM/فيروسات) — ✅ منفَّذ.
2. "Wazuh محدود في المصادر: Windows وLinux وMac".
3. الرؤية: مراقبة **الهواتف** بجميع أنظمتها، ربط **السويتشات والراوترات** ومراقبة ترافيك الشبكة، تجميع كل شيء في "قاعدة بيانات كبيرة"، وجعل الـ Agents **تدافع تلقائياً** ("إذا لقيت كذا تفعّل كذا").
4. "نطوّر Wazuh ليكون أداة ثانية وأقوى".

## 2. تصحيح فرضية "Wazuh محدود"
Wazuh **ليس** محدوداً بأنظمة التشغيل ذات الوكيل. يدعم أصلاً مصادر **بدون وكيل (agentless)**:
- **Syslog remote** (`<remote><connection>syslog</connection><port>514</port><protocol>udp</protocol><allowed-ips>192.168.100.0/24</allowed-ips></remote>`) — أي راوتر/سويتش/جدار ناري يُرسل syslog.
- decoders مضمَّنة: Cisco IOS/ASA، pfSense، Fortigate، Sophos، MikroTik (جزئي)، وقابلة للإضافة.
- **Agentless monitoring** عبر SSH لأجهزة الشبكة (فحص تغيّر الإعدادات).
- **Suricata على gateway** يراقب ترافيك أي جهاز — بما فيها الهواتف — بلا وكيل.

→ المطلوب ليس "أداة أقوى من Wazuh" بل **توسعة مصادر Wazuh + طبقة استجابة أذكى**. هذه صياغة أكاديمية سليمة ومقبولة للجنة.

## 4. توصية للفريق
- **قبل المناقشة (إن توفر أسبوعان):** UC-09 (SQLi) + UC-10 (Telegram) + UC-11 (brute-force → firewall-drop) + UC-12 (راوتر واحد عبر syslog). هذه الأربعة تحقق جوهر الرؤية ("ندري بكل شيء" + "الوكيل يدافع") بجهد معقول وتُعطي عرضاً حياً قوياً.
- **في الرسالة:** فصل 5 → "الأعمال المستقبلية": الهواتف عبر MDM، Zeek، TheHive، AI.
- **صياغة العنوان لا تتغير** — يبقى "SOC مفتوح المصدر"؛ التوسعات تُقدَّم كـ "قابلية التوسع (Scalability)" وهي نقطة قوة في التقييم.
